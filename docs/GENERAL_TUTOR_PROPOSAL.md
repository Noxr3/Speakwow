# Speakwow：从口语课程到长期私人教师

研究日期：2026-11-19。阶段 1、2 已实现，待合并、部署及真人试课。两门试点课各含 4 个教学单元和一次独立综合考核。阶段 3、4 在试点之后实施。

建议把 Speakwow 定义为：**一个记得你、按目标组织学习、能和你一起练习的私人教师。** 英语是其中一类课程；学科、授课语言和老师人格分别建模。底层可扩展到多学科，首批产品继续聚焦 AI 创始人。

本次核对了 Mr. Ranedeer 的实际提示词、相关项目的官方仓库与许可证、2025–2026 年论文，以及 Speakwow 当前课程 schema、教学状态机、材料工具和分类实现。外部项目功能主要依据其公开文档，未对其部署或教学效果做独立验收。以下产品设计是基于这些证据的建议，不是研究已经证明的 Speakwow 效果。

**1. Mr. Ranedeer 真正值得借鉴什么**

它的核心是把教学过程写成一套可配置协议：学生配置 → 先修课程 → 主课程 → 分段授课 → 练习测试 → 继续。实际提示词会要求准备示范题，再给简单熟悉、复杂熟悉、复杂陌生的题；允许答疑后回到课程。它抓住了“老师应有计划、应该等学生回应、应该检查迁移”的要点。[实际提示词](https://github.com/JushBJJ/Mr.-Ranedeer-AI-Tutor/blob/main/Mr_Ranedeer.txt)

但它仍主要依赖模型遵守文本协议，没有在这份提示词中建立独立持久化的学习证据、可靠的课程版本与程序化完成条件。自选高中/博士深度也不能证明真实水平。视觉型、主动型等配置更适合作为可调整的呈现偏好，而不是固定能力标签。代码环境内编码文本的做法不提供教学质量保证，无须继承。

仓库 README 已标记 DISCONTINUED；本次仓库元数据没有识别出许可证，根目录亦未发现 LICENSE。可以研究设计，但不把公开提示词直接当作获得了宽松授权的产品代码。[仓库](https://github.com/JushBJJ/Mr.-Ranedeer-AI-Tutor)

**3. 研究对产品的具体要求**

| 研究 | 观察与证据边界 | 产品决策 |
| --- | --- | --- |
| [Kestin 等，Scientific Reports，2025](https://www.nature.com/articles/s41598-025-97652-6) | 在大学物理教学场景的随机试验中，按教学原则设计的 AI 教师获得了较好的即时学习结果；不能外推为所有学科、长期学习都优于人类教师 | 预备目标、范例和问题，控制单次信息量，再通过互动检查学习 |
| [Bastani 等，PNAS，2025](https://doi.org/10.1073/pnas.2422633122) | 高中数学试验中，无约束 AI 提高练习表现，但移除 AI 后的考试表现更差；有教学约束的版本主要消除了这种伤害，并未据此证明独立考试成绩显著提高 | 把“AI 帮我完成”与“我独立会做”分开记录；提示后的正确回答不能直接算独立掌握 |
| [Khan Academy 团队，AIED 2026](https://arxiv.org/pdf/2608.11259) | 把教学行为离线评估与线上实验结合；关键指标之一是学生随后独立作答的下一题正确率。这属于产品方法与实验报告，不等于长期能力已全面验证 | 每次提示词、模型或活动改动都跑固定教学案例；用独立新题检查改动收益，同时监控错误反馈和答案泄露 |
| [DeepTutor，2026 技术报告](https://arxiv.org/abs/2604.26962) | TutorBench 包含基于学习者画像的模型模拟评价；所报个性化指标提升不能直接换算成真人学习增益 | 模拟学生用于回归筛查，真实学习效果仍用真人独立测验与延迟复习检查 |
| [Khosravi 等，2026 框架论文](https://arxiv.org/abs/2605.04816) | 提出把教学、对学习者的适应和负责任设计结合起来，强调即时任务表现与持续学习的区别；属于框架及案例分析 | 学习档案需要记录证据、误解和自我判断，不能只有聊天摘要或完成百分比 |

这些证据支持建立教学闭环，但没有证明某一种完整架构必然最优。角色扮演、小游戏和自然语音的具体效果仍需 Speakwow 自己验证。

**4. 用户体验：同一个老师，可以换学科**

入口允许三种意图：选现成课程、说出学习目标、带自己的材料来学。自然语言入口例如：“我想学统计，能判断我们产品实验有没有效果，每天 15 分钟，用中文。”

老师只追问影响方案的缺失信息，例如已有基础和具体目标，再通过少量任务做初步诊断，给出可编辑的大纲与第一课。初步诊断是暂定判断，可以随证据修正。先生成可审阅的路线和首个单元，后续内容逐步准备，避免一次制造几百节未经验证的课程。

首页延续现有设计语言与两块信息结构：较矮的当前课程区域，以及下一节课/单元卡片。主动作是继续学习；换课程、新建课程在课程页。没有课程时保留选择课程与自由交流入口。Profile 中查看目标、学习记录和复习建议，不在首页铺开知识图谱、模型设置和分析面板。

课程页面按学科/目标导航。英语课程显示适用 CEFR；统计课程显示先修知识与预期能力。一个人可以数学基础扎实、英语 B1，也可以英语 C2、编程零基础。**学科水平、授课语言、语言学习目标必须是三个独立维度。**

老师人格影响声音、语气与讲解习惯；教学能力由课程材料、活动和验证工具支持。切换 Frank 或其他老师应保留同一份学科进度，不重新开始。

**5. 一节课怎样真正像上课**

推荐默认 10–20 分钟，可缩短或延长；时长是体验起点，不是完成标准。

| 环节 | 老师与学生的互动 | 留下的证据 |
| --- | --- | --- |
| 接续 | 简短聊近况，回顾上次卡住的地方，约定今天解决的问题 | 目标、已有理解 |
| 示范 | 一个短解释配一张例子卡；必要时老师直接讲清楚 | 学过什么，不计独立掌握 |
| 一起做 | 学生操作或回答；先给小提示，再按需要增加支持 | 尝试、错误类型、提示程度 |
| 独立做 | 新题或新情境，学生自己解释、判断、写作或执行 | 独立表现与具体作品 |
| 收尾 | 说清已会什么、还差什么，询问下一节、休息或结束 | 课节完成状态、复习安排 |

教学可以直接解释，也可以提问。学生困惑时先给清楚的范例，再逐步撤去支持；避免老师一直反问、让学生猜。

发散时保留主线位置与未完成任务。相关话题可以变成补充例子；较远的话题先短聊，再自然询问是否回来，或保存为以后学习的主题。只有学生确认进入下一节后才推进教学。暂停、聊天、看过答案、说“懂了”都不自动完成目标。学生可以主动跳过，但记录为跳过而非掌握。

例子：“今天你已经能识别诱导式访谈问题。接下来可以练习追问客户的真实行为，也可以先休息一会儿。”

**6. 保留语音优势，增加能动手的学习桌面**

| 学科 | 语音承担什么 | 卡片/工具承担什么 | 判断是否学会 |
| --- | --- | --- | --- |
| 客户访谈、谈判 | 扮演客户，追问，复盘 | 背景资料、提问排序、观察笔记 | 换一个客户后能否提出非诱导问题、区分证据与推测 |
| 统计与实验 | 解释假设，讨论结果 | 数据表、可操作图表、计算步骤 | 用新数据独立计算并解释局限；数值由工具验证 |
| 编程 | 解释思路、提示调试 | 可运行代码、输出、测试结果 | 学生代码通过测试，并能解释与修改；不能仅凭口述判定 |
| 历史、人文 | 讨论与比较观点 | 原始材料摘录、时间线、证据卡 | 能否引用证据、识别反例、构成论证；承认合理的多种答案 |
| 英语 | 实时口语、听力、角色扮演 | 阅读、写作、听写、图片 | 按对应语言能力目标评价 |

小游戏作为教学活动进入课节：找出访谈问题里的陷阱、猜图表变化、给证据排序、反向当老师解释错误、在新情境里完成任务。每个游戏必须绑定学习目标与可观察表现；游戏分数不直接等于掌握度。

纯语音先覆盖适合讨论和口头推理的内容。代码、数学推导、图形等需要对应输入与验证工具后再作为完整课程发布；实际身体技能还需要观测与现实练习，不能靠会谈就宣称掌握。

**7. 适合现有仓库的技术方案**

当前 `courses/schema/course.schema.json` 已含 `subject`、`teaching_language`；单元目标已支持 concept、skill、application、reasoning。`curriculum.py` 已有课节与聊天/休息/考核状态。因此可在原模型上增量扩展。

主要缺口：`apps/web/lib/course-categories.ts` 仍按英语分类；`materials.py` 仅支持 picture/reading/writing/dictation，图片限于四个预设场景；`lesson.py` 从结构化字段组装教学上下文，不能假设新增 Markdown 教案正文就会被教师读到。现有 0.8 阈值是产品进度规则，不是经过校准的跨学科能力测量。

建议新增或明确五类对象：

| 对象 | 最少包含什么 |
| --- | --- |
| CoursePackage | 稳定 ID、版本、适用人群、可观察结果、先修条件、来源及版本/授权/引用位置、审核状态 |
| Concept / Skill | 稳定概念 ID、少量先修关系、典型误解、可用活动；初期用关系表，无须另建图数据库 |
| LessonPlan | 目标、讲解材料、示范、练习、提示梯度、独立检查、评分规则、完成条件、补救分支 |
| Evidence | 原始回答/作品引用、时间、题目版本、使用过的提示、评估器及版本、评价依据、不确定性 |
| LearnerState | 分学科技能状态、近期证据、复习日期；全局偏好与学科能力分开，允许用户查看和纠正 |

完成一节课与长期掌握分开存储。能力状态可表达为未检查、正在学习、可独立完成、需复习。一次考试通过产生“在该任务条件下通过”的证据；长期掌握需要多次表现和延迟检查，不能从单次模型分数生成虚假的精确概率。

教学运行时继续由一个实时教师主持。课程规划、文件解析、检索索引与后续材料准备放在后台；语音回合优先使用当前已准备的教案和材料，只在必要时调用工具。评分使用独立职责与证据约束，但“另一个模型打分”本身不保证正确：计算/代码优先执行验证，开放题配量规与人工抽查。

通话会话、教学课节、练习提交与课程进度继续分离。保持原有稳定 ID 与旧进度；增加版本映射后再升级课程。提交幂等、断线恢复、成功持久化后再推进状态仍是必要条件。

公共材料按来源版本缓存；私有上传与个性化状态按用户权限隔离。后台预取下一课，显示可恢复的准备状态，避免把整个课程生成过程放在“开始课程”按钮之后。观察选课到内容显示、开始到可对话、语音响应的 p50/p95，并与当前基线比较。

FSRS 一类调度可先用于事实、术语和短答案提取；推理、代码与项目能力另用变式任务和作品复查。不要把所有学科都转换成闪卡。

**9. 推荐实施顺序与验收**

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 验证通用教学闭环 | 面向 AI 创始人的中文“客户访谈与需求判断”：4 个教学单元，加综合任务；目标、量规、证据与明确结束 | 能诊断、讲解、演练、独立检查、闲聊后返回、结束后询问下一步；现有英语课程与进度无回归 |
| 2. 验证第二学科 | “产品实验与统计判断”：采用许可明确的统计材料，增加表格/图表与计算验证 | 新数据上的独立表现有可复核结果；统计能力与英语能力分别记录；材料来源可追溯 |
| 3. 开放自建课程 | 上传材料或描述目标，生成可编辑路线与首个单元；后台准备后续内容 | 生成课程标记为未审核；先修关系无环；每个目标有活动和检查；缺失来源/无法可靠验证时明确提示范围 |
| 4. 增加专业学习工具 | 编程运行环境、更多可交互材料、按学科适配复习 | 作品能执行和验证；隔离运行；移动端能完成核心任务；不能支持的练习不包装成已支持 |

第一阶段不要求一次重写现有 AI 创始人英语 B1–C2 草案。把其中客户沟通活动作为候选教学素材，另行编写非语言课程；英语目标继续留在原课程中。

效果验证先做小规模可用性与教学错误测试，再根据前测方差确定正式对照评估样本。固定独立前后测及约一周后的新题复查，分别观察学科迁移、提示依赖、主动解释质量；同时报告流失与参与情况。小样本访谈可以发现问题，不能宣称证明学习增益。

每次模型或提示词升级保留回归集：错误答案被夸对、正确答案被否定、提示后误判掌握、课程结束仍继续教、发散后丢失主线、无依据引用、断线后重复计分。聊天时长、连胜和满意度用于体验观察，独立任务表现才是主要学习结果。

推荐首先做出两门可检验的跨学科课程，确认“同一个老师带你学会不同东西”的体验，再扩展课程生成与目录规模。
